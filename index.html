rupak101 / playwright-typescript-test

A Playwright + TypeScript framework set up for AI-assisted testing

A public demo framework that shows how I structure UI tests. It runs against a public practice web shop.

  • Page Object Model with a BasePage and a PageFactory, injected into tests through custom fixtures.
  • Data-driven specs, with test data and expected UI text kept in their own folders.
  • Strict TypeScript, ESLint, Prettier and Husky as gates before any commit.
  • Docker and GitHub Actions, with Allure and HTML reports.
  • A custom failure reporter that groups failed tests by their first error and gives a rerun command for each.

How the AI works inside the rules

  1. CLAUDE.md loads the framework guide, so generated code follows the same rules as mine.
  2. The /add-test command explores the flow in a real browser first, reuses page objects, then runs the checks and the test until both pass.
  3. settings.json blocks the agent from reading .env and formats every file it edits.
  4. Lint, type checks and the tests reject generated code that breaks the rules, the same as hand-written code.

Selected work

Token.io · A2A payments
Problem

Testing asynchronous payments across APIs and a dashboard

Payments are asynchronous and finish later, so UI tests alone would be slow and fragile.

Approach
  • Most coverage at the API level, a few end-to-end tests for key journeys.
  • One helper per API endpoint, reusable fixtures, setup files that only create data.
  • Tests poll each payment until a final state and fail fast with the payment ID, traced in Kibana.
Result
UI end-to-end · key journeysAPI tests · most coverage

✓ quality gate on every pull request

The team uses CI to decide whether a release can go out.

Problem

15% of test runs failed for reasons unrelated to the code

When red builds are normal, people stop trusting CI and start rerunning it.

Approach
  • Fixed waits replaced with polling for the real status.
  • A fresh test member per test instead of shared accounts, so tests run in parallel.
  • Environment issues taken to the right team with evidence.
  • Retries only in CI, reported as flaky, and the flake rate tracked as a metric.
